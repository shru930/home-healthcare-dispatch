# BPMN models and forms

| File | Process ID | Purpose |
|---|---|---|
| `main-home-healthcare.bpmn` | `home-healthcare-dispatch` | Main seven-day home-care process |
| `pharmacy-prescription-fulfillment.bpmn` | `pharmacy-prescription-fulfillment` | Reusable child process, invoked by the call activity `Call_Pharmacy` |
| `forms/*.form` | 7 Camunda Forms | `health-assessment-form`, `doctor-review-form`, `physio-session-form`, `manual-nurse-form`, `correct-discharge-form`, `manual-emergency-form`, `gap-review-form` |

## Deploy
Deploy the child process first, then the main process with the forms:

```bash
node tools/deploy.js            # uses CAMUNDA_REST_ADDRESS or http://localhost:8080
```

You can also open the files in Camunda Modeler 5.50 and deploy them to *Camunda 8 Self-Managed* (c8run).

## Mandatory constructs

| Construct | Element ID | Configuration |
|---|---|---|
| Sequential multi-instance | `Sub_DailyVisit` | `=carePlanDays` → `careDay`, output `visitResults` |
| Parallel multi-instance | `Sub_Physio` | `=physioSessions` → `session`, output `physioResults` |
| Parallel multi-instance call activity | `Call_Pharmacy` | `=prescriptions` → `prescription`, calls `pharmacy-prescription-fulfillment`, output `pharmacyResults` |
| Sub-process with error and timer boundaries | `Sub_RiskIntervention` | `Err_EmergencyDispatch` (`EMERGENCY_DISPATCH_FAILED`), `Timer_InterventionTimeout` (`=interventionTimeout`) |
| REST outbound connector | `Task_DistanceMatrix`, `Task_SmsAssignment`, `Task_SmsCritical`, child `Task_SmsDelayed`, `Task_SmsDelivered` | `io.camunda:http-json:1`, secrets via `{{secrets.*}}` |
| Email outbound connector | `Task_EmailAssignment`, `Task_EmailFinal` | `io.camunda:email:1` (SMTP), error expression → `NOTIFICATION_FAILED` |
| Error boundaries | `Err_DistanceApi`, `Err_DistanceInvalid`, `Err_NoNurse`, `Err_EmailAssign`, `Err_SmsAssign`, `Err_EmailFinal`, child `Err_Courier` | |
| Timer boundaries / events | `Timer_VisitWindow`, `Timer_PhysioWindow`, `Timer_DoctorReminder` (non-interrupting), `Timer_InterventionTimeout`, child `Timer_DeliveryReminder` (non-interrupting), `Timer_DeliveryTimeout`, intermediate `Timer_NurseRetry` | |

The models are generated by `tools/build_bpmn.py`, which keeps IDs, job types and variable names consistent with the Java workers. Edits made in Camunda Modeler are fine as well.
